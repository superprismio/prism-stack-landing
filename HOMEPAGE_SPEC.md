# Prism Stack Homepage Spec

## Positioning

> **Prism Stack is infrastructure for collaborative AI communities.**

## Tagline

> **Shared intelligence for communities**

## Goal

Position Prism Stack as:

- a deployable stack for community AI workflows
- infrastructure for shared memory, knowledge, and operator tooling
- a Discord-first entry point into broader collaborative AI systems
- a credible product for communities that need control over context and deployment

The homepage should feel like:

**applied infrastructure + collaborative intelligence + live systems**

Not:

- a generic SaaS landing page
- a solo chatbot product
- a vague AI manifesto

## Voice

The tone should align with the current Superprism site:

- systems-oriented
- research-informed
- technically credible
- calm and minimal

But Prism Stack should read as more deployable and operational than the R&D lab framing.

## Core Story

Most AI tools are built for individuals.

Communities work across:

- Discord channels and threads
- meetings and calls
- docs and handbooks
- repos and contributor workflows

Prism Stack gives communities a way to:

- capture shared context
- turn meetings into durable artifacts
- organize memory and knowledge
- run operators and agents against real community context
- keep more sovereignty over infrastructure and data

## What It Solves

### Shared context loss

Important discussions, decisions, and meeting outcomes disappear into chat and voice.

### Repeated synthesis work

Operators keep re-explaining the same background because context is fragmented.

### Weak AI collaboration surfaces

Most AI products help one person at a time, not teams working across shared context.

### Poor continuity

Communities lose momentum when context is trapped in threads, inboxes, or private notes.

### Low control

Communities that care about privacy, local context, or custom workflows need more than a hosted assistant.

## Key Product Highlights

- Discord-first workflows
- shared memory and knowledge
- meeting transcripts and summaries
- operator chat and runtime actions
- deployable stack on infrastructure you control
- configurable ingestion and policy

## Primary Use Cases

- open source communities
- research collectives
- DAOs and contributor networks
- agencies and distributed teams
- communities building AI-assisted coordination workflows

## Homepage Structure

1. Hero
2. Problem
3. Capabilities
4. Use Cases
5. Workflow / System View
6. Why It Matters
7. CTA

## Section Guidance

### Hero

Headline options:

- Prism Stack. Infrastructure for Collaborative AI Communities.
- Shared intelligence for communities, not just individual users.
- Memory, knowledge, and agent workflows for communities.

Supporting copy:

- Prism Stack helps communities turn chat, meetings, docs, and repos into usable shared context. Start with Discord. Build toward durable community memory, knowledge, and operator workflows.

Primary CTA:

- Explore the Stack

Secondary CTA:

- View the Architecture

### Problem

Headline:

- AI tools are built for individuals.

Body direction:

- Communities need shared context that survives meetings, threads, docs, and turnover.

### Capabilities

Suggested callouts:

- Discord ingestion
- Meeting capture
- Shared memory
- Knowledge sync
- Operator workflows
- Deployable infrastructure

### Use Cases

Show concrete domains:

- open source operations
- contributor onboarding
- governance coordination
- meeting capture and follow-through
- knowledge continuity for distributed teams

### Workflow / System View

Show one or two clear flows:

- Discord conversation -> memory artifact -> searchable knowledge
- Voice meeting -> transcript + summary -> linked artifacts
- Operator prompt -> runtime action -> updated context or workflow result

### Why It Matters

Framing:

- The next problem is not just better AI answers.
- The problem is how communities build and govern shared context with AI in the loop.

### CTA

Good CTA directions:

- start with the template
- deploy your own instance
- explore the architecture

## Visual Direction

Reuse the current Superprism visual language:

- Space Grotesk + Space Mono
- hard-edged cards
- dark theme
- green/purple signal colors
- strong backgrounds and technical diagrams

Keep:

- crisp borders
- sparse but strong imagery
- research-interface feel

Avoid:

- generic SaaS gradients
- soft rounded card-heavy composition
- oversized marketing fluff

## Notes for Implementation

- Keep the branding intentionally aligned with Superprism.
- Shift the copy from “R&D lab” toward “deployable stack.”
- Emphasize community coordination and shared intelligence.
- Show Discord as the current entry point, not the full long-term surface.
- Use real screenshots and workflow references when possible.
